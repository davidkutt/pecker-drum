# M2.1: Sources per attempt

Read `AGENTS.md`, `docs/spec.md` (sections "HTTP targets" and "Runner and reports"), ADR 0008 and
ADR 0009 first. One pull request against `main`.

## Why

A blocked `indirect_doc` attempt doesn't say whether the target retrieved the planted document. So
"blocked" mixes two different results: the model saw the attack and resisted, or the retriever never
surfaced it. In the first private run every blocked indirect attempt was ambiguous for that reason.
The targets already return sources (`Observation.sources`), but neither the JSON report nor the run
record keeps them: `AttemptResult` in `src/pecker_drum/results.py` has no field for them.

## Deliverables

1. Every attempt records the ids of the sources the target returned, in the target's order and without
   duplicates. Ids are escaped like the other excerpts and redacted as the HTTP target does today.
   Source texts stay out: they can be long and can hold private documents. If the plan needs them,
   ask David.
2. Every attempt of an item that plants fixtures records whether a planted fixture was among the
   sources: retrieved, not retrieved, or unknown (the target doesn't expose the sources channel).
3. The JSON report and the run record carry both. Run records written before M2.1 still load and
   render with `drum report --run-id`.
4. The Markdown report shows, per item, how many attempts retrieved the planted fixture.
5. `docs/spec.md` describes the new fields. An ADR only if the plan makes a real decision.

## Decisions to settle before the plan (`/skill:grill-me`)

- How a planted fixture is recognised among the sources, for the twin and for HTTP targets. Read the
  code before you ask.
- What items without planted fixtures (`direct`) record.
- How records from before M2.1 show the new fields.

## Acceptance checks

- [ ] Lint, format check, Pyright, tests and the four self-tests in CI (twin and stand-in) pass;
      self-test outcomes unchanged.
- [ ] A stand-in run shows the source ids and the retrieved state per attempt in the JSON report and
      the run record, and the per-item count in the Markdown report:
      `uv run drum run --target stub --set public_v1 --model fake:obedient --vectors direct,indirect_doc`
- [ ] Tests cover all three states: a planted fixture among the sources (retrieved), sources without it
      (not retrieved), and a target that doesn't observe sources (unknown).
- [ ] A run record from before M2.1 (a test fixture) loads and renders with `drum report --run-id`.
- [ ] A source id with a control character and one with a token in it come out escaped and redacted.
- [ ] `docs/spec.md` is updated in the same pull request.
