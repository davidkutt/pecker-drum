# M1.3: Supply-chain and CI hardening

Read `AGENTS.md` and `.github/workflows/ci.yml` first. Small milestone, one pull request against
`main`, on a new branch from `main` (independent of the open M1.2 PR). Add this brief as
`docs/milestones/M1.3.md` in the same pull request (David allows that path for this PR).

## Why

pecker-drum is a public security tool. Its own repo should pass the checks it would ask of others:
pinned actions, least privilege, known-vulnerable dependencies caught early, and the invisible-character
rule enforced where agents can't forget it.

## Deliverables

1. **Pin every GitHub Action to a full commit SHA**, with the version as a trailing comment
   (`uses: actions/checkout@<sha> # v5.x.y`). Keep `permissions: contents: read` at the top and set
   per-job permissions only where a job needs more.
2. **Dependabot** (`.github/dependabot.yml`): weekly updates for `github-actions` and `uv`, grouped
   minor and patch updates, a small open-PR limit. If the `uv` ecosystem isn't available, say so in
   the PR and fall back to `pip` with `uv.lock` left alone.
3. **Dependency audit job:** export the locked dependencies (`uv export --frozen`) and run
   `pip-audit` on them in CI (via `uvx`, not as a project dependency). A known vulnerability fails
   the job; an ignore list needs a reason and an expiry date per entry.
4. **Workflow lint:** run `zizmor` on `.github/workflows/` in CI (via `uvx`) and fix what it reports.
   Never interpolate event fields (`${{ github.event.* }}`) into `run:`; pass them through `env:`.
5. **Commit-message and PR-text guard:** a CI step on pull requests that fails on Unicode Cf/Cc
   characters (except tab, LF, CR) in every commit message of the PR range and in the PR title and
   body (read through `env:`, see item 4). Move the checker from `tests/test_docs_text.py` into a
   dev-only script `tools/text_guard.py` (not part of the package), import it from the test, and use
   the same script in CI, so there is one checker, not two.
6. **`SECURITY.md`:** how to report a vulnerability in pecker-drum (GitHub private vulnerability
   reporting), what is in scope, and the responsible-use rule from `AGENTS.md` (only targets you own).
   Pseudonymous: "David" / `davidkutt` only.

## Acceptance checks

- [ ] CI is green on the PR, including the new audit, zizmor and guard steps.
- [ ] `zizmor` reports nothing above "informational"; if something stays, the PR explains why.
- [ ] A unit test feeds the guard a commit message and a PR body that contain a real U+200B (built
      from the escape inside the test) and expects a failure naming the code point. No throwaway
      branches.
- [ ] No change to `src/`, `items/`, `fixtures/`, `README.md` or `docs/spec.md` (M1.2 and M2 touch
      those). Note README changes you'd like (badges, security section) in the PR description.

## Out of scope

Branch protection and repository settings (David does those), signing, releases.
