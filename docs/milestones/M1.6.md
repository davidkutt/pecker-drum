# M1.6: No hidden characters in code

## Why

AGENTS.md forbids Unicode format and control characters (Cf/Cc) in docs, commit messages and code outside fixtures/ and items/, but the guard (tools/text_guard.py, tests/test_docs_text.py) only scans docs. Six test lines on main hold literal characters where escapes were meant, including U+202E RIGHT-TO-LEFT OVERRIDE, which GitHub flags as hidden bidirectional text. Agent tooling turns typed escapes into real characters, so this recurs unless a test catches it.

## Deliverables

1. Replace the literal characters with Python escapes (for example \u200b) so every string keeps exactly the same value:
   - tests/report/test_excerpt.py lines 12, 19, 24 (U+200B; U+202E)
   - tests/grading/test_links.py line 107 (U+200B)
   - tests/grading/test_normalise.py lines 32, 39 (U+200B, U+200C, U+200D, U+2060, U+FEFF, U+00AD; U+202E)
   Line numbers are from main at 19d803a. Find and fix them with a script, not by typing.
2. Widen the guard to every tracked UTF-8 text file outside fixtures/ and items/ (src/, tests/, tools/, .github/, pyproject.toml, docs). One checker, still in tools/text_guard.py. Say in the PR how lock and binary files are handled.
3. AGENTS.md: replace "A test checks tracked docs." with "A test checks every tracked text file outside fixtures/ and items/."

## Acceptance checks

- [ ] Lint, format check, Pyright, tests and both self-tests pass; self-test outcomes unchanged.
- [ ] The widened guard passes on the whole tree and reports a literal U+200B planted under src/ or tests/ (in tmp_path).
- [ ] The PR description shows that every changed string literal has the same value before and after (for example by comparing ast.literal_eval of the old and new lines).
