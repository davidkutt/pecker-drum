# M2.2: M2.1 follow-up

Read `AGENTS.md` and ADR 0010 first. One pull request against `main`. A small cleanup: no new
behaviour, no new fields.

## Why

Reviews of M2.1 (blind reruns of the snapshot before its last fix) left six points that still apply
to `main`. The most important one: nothing checks the twin's `retrieved` state end to end. If the
twin stopped printing `[<doc_id>]` in its tool output, every test would stay green while every
twin attempt quietly turned `not_retrieved`.

## Deliverables

1. **An end-to-end test of the twin's retrieval state.** `tests/test_cli.py`
   `test_obedient_and_safe_self_tests_pass` checks outcomes only. Extend it (or add a test next to
   it) so that both runs' JSON reports record what the twin does today: `DOC_ITEM` is `retrieved`
   with signal `both`, and `TOOL_ITEM` is `retrieved` with signal `canary` (its `scenario:`
   fixture's canary is in the tool result, ADR 0010 section 2). Assert the signal exactly, not
   only the state: without the brackets the canary still matches, so a state-only test can't
   fail.
2. **No import from `results.py` into `grading/`.** `grading/retrieval.py` imports `RetrievalState`
   and `RetrievalSignal` from `results.py`, which imports `report/excerpt.py`; `results.py` works
   around the cycle with a `TYPE_CHECKING` block. Make the grading layer stop depending on
   `results.py` and drop the `TYPE_CHECKING` workaround. Callers and tests that import the enums
   follow.
3. **ADR 0010 says what the code does.** Section 4 lists "a planted fixture had no usable marker"
   as a reason for `unknown`, and section 5 says one such fixture "makes the attempt `unknown`".
   The code and `test_a_match_counts_even_when_another_fixture_has_no_signal` say a match wins:
   `retrieved`. Add "and nothing matched" (or equivalent) in both places. No other change to the
   ADR's decisions.
4. **No default for `planted`.** `targets/http/target.py` `_Collector.build(…, planted=())`: drop
   the default, so a new call site can't forget to report what it planted.
5. **The `Target` protocol says it.** `targets/base.py` `Target.run` docstring: a target that plants
   fixtures fills `Observation.planted` (ADR 0010).
6. **A made-up canary in the old record.** `tests/campaign/data/record-pre-m2.1.json` uses the real
   canary of `fixtures/documents/runbook-cache-restart.md` (lines 73, 76 and 77 on `99e7323`).
   Replace it with a made-up one in the same format, unless a test relies on it matching the
   fixture (then say so in the plan and leave it).

## Decisions to settle before the plan (`/skill:grill-me`)

- Item 1: whether to read the JSON report the run writes or the run record, and how to find the
